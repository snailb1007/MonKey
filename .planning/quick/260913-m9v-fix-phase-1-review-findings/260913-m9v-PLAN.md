# Quick Plan: Fix Phase 1 Code Review Findings

## Context
During Phase 1 code review, 4 findings were identified and verified:
1. `matches_set` in `crates/monkey-core/src/device.rs` paired unrelated devices due to `DevSrvsID` proximity $\le 32$.
2. `monkey probe` in `crates/monkey-cli/src/commands/probe.rs` hardcoded `rev1.0` and `v1.0.0` regardless of response.
3. Fallback `probe_device_without_transport` defaulted to `WiredUsb` even when `set.is_wireless()` was true.
4. `evaluate_state_query` in `crates/monkey-core/src/transport/hid.rs` treated `Ok(0)` as `WirelessAwake`.

## Tasks

### Task 1: Fix `matches_set` pairing in `crates/monkey-core/src/device.rs`
- Remove naive `abs_diff <= 32` pairing heuristic across unrelated interfaces when multiple candidates exist. Check interface paths and composite device grouping.
- Ensure regression tests verify multiple concurrent devices do not cross-pair.

### Task 2: Fix `evaluate_state_query` 0-byte handling in `crates/monkey-core/src/transport/hid.rs`
- Require `len > 0` and valid response payload before marking `WirelessAwake`.
- Treat `Ok(0)` as `WirelessSleeping`.

### Task 3: Fix probe firmware parsing & fallback in `crates/monkey-cli/src/commands/probe.rs`
- Avoid hardcoding `rev1.0` / `v1.0.0`. Parse actual response or mark as `unknown` / unverified.
- In `probe_device_without_transport`, set `TransportState::WirelessSleeping` or appropriate wireless state if `set.is_wireless()`.

### Task 4: Run test harness and update unit/integration tests
- Update `tests/cli_probe_test.rs` and verify with `cargo test --workspace`.
