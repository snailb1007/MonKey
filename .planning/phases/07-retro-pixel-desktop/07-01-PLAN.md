# 07-01 — Safe native desktop adapter and contract tracer

## Objective / ownership
Deliver real Tauri v2 native command adapter and safety tests, not a shell-out wrapper or fake-success stub. Own ONLY apps/desktop/src-tauri/**, apps/desktop/contracts/ipc-v1.json and this plan's SUMMARY. Native Cargo.toml uses its own [workspace] and path-depends on ../../../crates/monkey-core; do not modify root Cargo.toml/Cargo.lock, core/CLI, frontend files or sibling SUMMARY. All native manifests, lockfile, build.rs, tauri.conf.json, capabilities, icons and entitlements belong to this card. Minimum native permissions, no global filesystem/shell/network grants; no signing certification claim.

## Required context / contracts
Read 07-UI-SPEC.md, 07-RESEARCH.md and 07-CONTEXT.md next to this plan (canonical source on main checkout until planning commit). The full locked IPC v1, bounds, state and screen parity are normative. React/TS Vite frontend will live one directory above src-tauri; devUrl http://localhost:1420, frontendDist ../dist, backend's beforeDevCommand `pnpm run dev`, beforeBuildCommand `pnpm run build` run from apps/desktop. Identifier `dev.monkey.desktop`, product MonKey, title MonKey, default 1040x720 minimum 760x560. No frontend exists during this card: library verification cannot depend on generated frontend dist. Native-only tests must not generate_context! or require UI distribution files; production binary context is verified in 07-02.

Shared decisions (also carried by frontend card): only invoke desktop_request({request}); version 1 camelCase envelopes, snake_case action tags; list_devices/probe/diagnostics/pick_asset/start_lcd/stop_lcd/job_status/rgb_status/rgb_preview/rgb_commit/export_profile/import_profile. Opaque device/asset/job IDs, no JS paths/opcodes, typed ok/error union, per-request ID stale-result protection. A 0xFF68:0x0061 handles LCD, B 0xFFFF/config handles RGB; existing InterfacePolicy may require both. Backend deny remap/macro/firmware/raw writes even if frontend is bypassed. Single serialized worker, RAM preview <=30Hz, no implicit flash; explicit commit respects native 500ms debounce/read-before-write/readback and <20% wireless battery block (unknown battery also blocks wireless persistence). Demo opt-in never opens hardware. Use exact native enums/ranges, publish fixtures. Do not implement speculative opcodes from Scout prose.

## Tasks
1. Build failing native contract/device-tracer tests first: deserialize allowed/malformed/unknown requests, run list/probe through mock adapter, prove no configuration writes. Implement bounded DTO parsing, error mapping and opaque sessions. Emit Rust-generated fixtures for each action/result/error in contracts/ipc-v1.json; tests assert fixture equality and enum/range fidelity. Never include serial/path PII.
2. Wire Tauri startup and one serialized hardware owner using existing MonkaDevice/InterfacePolicy/SafeTransport, never raw unrestricted Transport. Native blocking work cannot block UI executor. Handle disconnect, device switch, duplicate requests, busy jobs and orderly app-close stop/cleanup. No detached runaway hardware worker. Implement native diagnostics and permission guidance.
3. Implement scoped native asset picking/import and actual core conversion/streaming/pattern jobs, bounded decode and safe sequence traversal, PNG preview of converted RGB565. Poll status <=4Hz from UI contract, cancellation acknowledged. Test corrupt/oversized inputs, symlink escape, stale tokens, progress/stop races, LCD InterfacePolicy prerequisite rejection and zero I/O on rejection.
4. Implement RGB current state, RAM-only previews, explicit persistent intent, confirmed readback, battery gates and profile export/import with native choosers. No flash on preview/import/close; no unknown modes. Mock call-trace tests prove no writes for remap/macro/firmware, unauthorized capabilities, low/unknown wireless battery and malformed inputs; valid ops preserve existing pacing/safety APIs.
5. Harden CSP/capabilities; no remote content, generic command/shell, network, arbitrary JS file access or debug hardware fallback. Format owned changed files, perform graph analysis where available (UNKNOWN/failure is not clearance), run every gate below, write SUMMARY using $HOME/.hermes/gsd-core/templates/summary.md, commit code+SUMMARY. Report findings/ready_for_ce_compound, owned files, base/branch/head SHA and raw evidence logs; no core changes to clear a failing gate.
