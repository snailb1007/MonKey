# Plan 04-03: CLI monkey rgb Command Tree, Ergonomics & Headless Integration Tests

## Objective
Implement user-facing `monkey rgb` subcommands (`set`, `status`, `save`, `restore`) with input validation, human-readable terminal output, JSON output formatting, and automated CLI integration tests.

## Proposed Changes

### `crates/monkey-cli/src/commands/rgb.rs`
- Define `RgbCommand` clap enum with variants:
  - `Set { mode: String, color: Option<String>, speed: Option<u8>, brightness: Option<u8>, commit: bool, force: bool }`
  - `Status { json: bool }`
  - `Save { file: Option<PathBuf>, stdout: bool }`
  - `Restore { file: Option<PathBuf>, commit: bool, force: bool }`
- Implement execution handlers connecting to `RgbManager` over real or mock transport.
- Format user-friendly terminal output showing mode, parameters, and whether change is volatile RAM preview or permanent Flash commit.
- Support `--json` output across subcommands.

### `crates/monkey-cli/src/commands/mod.rs` & `crates/monkey-cli/src/main.rs`
- Register `rgb` subcommand in CLI tree.

### `crates/monkey-cli/tests/cli_rgb_test.rs`
- Integration tests using headless `MockTransport`:
  - `monkey rgb set static --color #FF0000 --mock` (RAM preview)
  - `monkey rgb set static --color blue --commit --mock` (Flash commit)
  - `monkey rgb status --mock --json`
  - `monkey rgb save --file <tmp> --mock`
  - `monkey rgb restore --file <tmp> --mock`
  - Error handling for invalid color, invalid mode, out-of-range brightness/speed.

## Verification
- `cargo test -p monkey-cli --test cli_rgb_test` passes.
- `cargo run -p monkey-cli -- rgb --help` shows complete command tree.
