# Plan 04-01: Ambient RGB Lighting Data Types, Packet Codecs & 81-Key Matrix Model

## Objective
Implement strongly typed domain primitives for ambient lighting (`LightingMode`, `RgbColor`, `LightingConfig`), feature report `04 13` packet serialization/deserialization, and the 81-key hardware LED matrix abstraction loaded from `research/layout_81keys.json`.

## Proposed Changes

### `crates/monkey-core/src/rgb/mode.rs`
- Define `LightingMode` enum with supported modes: `Static`, `Breathing`, `Wave`, `Rainbow`, `Ripple`, `Reactive`, `Off`, with protocol byte conversion.
- Define `RgbColor` with constructors `from_rgb(r, g, b)`, `from_hex(&str)` supporting `#RRGGBB` and `RRGGBB`, and named color aliases (`red`, `green`, `blue`, `yellow`, `cyan`, `magenta`, `white`, `off`).
- Define `LightingConfig` struct carrying mode, color, brightness (0..100), speed (0..100), direction, and color type.
- Implement validation rejecting invalid parameters.

### `crates/monkey-core/src/rgb/codec.rs`
- Implement encoder converting `LightingConfig` into a 64-byte `FeatureReportPacket` with opcode `0x13` (`CommandId::RgbControl`) and marker `[0xAA, 0x55]`.
- Implement decoder parsing 64-byte feature reports back into `LightingConfig`.
- Verify round-trip conversion and byte-level invariant guarantees.

### `crates/monkey-core/src/rgb/matrix.rs`
- Define `KeyDefinition` struct holding `name`, `row`, `col`, `rgb_light_index`, and `keycode`.
- Define `KeyMatrix` struct embedding `research/layout_81keys.json` by default.
- Implement lookup methods: `lookup_by_name`, `lookup_by_pos(row, col)`, `lookup_by_led_index(index)`.
- Support loading custom layout JSON files with schema validation.

### `crates/monkey-core/src/rgb/mod.rs`
- Module re-exports and public API surface.

### `crates/monkey-core/tests/rgb_codecs_test.rs`
- Unit tests verifying color parsing from hex and names.
- Unit tests verifying packet encoding/decoding and marker offsets.
- Unit tests verifying 81-key matrix indexing and lookups.
