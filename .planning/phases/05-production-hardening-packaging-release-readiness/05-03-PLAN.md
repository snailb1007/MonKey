# 05-03: POSIX Exit Codes, Error Categorization & `cargo-deny` Compliance

## Objective
Establish standard POSIX exit codes and user-friendly error diagnostics across all CLI commands. Update dependency configurations and `deny.toml` to guarantee 100% automated license, advisory, and ban audit compliance with zero warnings or errors.

## Proposed Changes
1. **POSIX Exit Codes (`crates/monkey-cli/src/error.rs`)**:
   - Define exit code constants / enum:
     - `EXIT_SUCCESS = 0`
     - `EXIT_GENERAL = 1`
     - `EXIT_USAGE = 2`
     - `EXIT_NO_DEVICE = 3`
     - `EXIT_PERMISSION = 4`
     - `EXIT_BLOCKED = 5`
   - Implement error classification logic:
     - Check error chains for `TransportError::DeviceNotFound` -> `EXIT_NO_DEVICE`.
     - Check error chains for permission / access denied / IOKit errors -> `EXIT_PERMISSION`.
     - Check error chains for safety violations (`Flash write throttled`, `Hardware writes require explicit consent`, `battery < 20%`) -> `EXIT_BLOCKED`.
     - Check clap parse errors -> `EXIT_USAGE`.
   - Update `main.rs` to format errors cleanly to `stderr` with informative prefixes and exit with the classified code.
2. **`deny.toml` and Workspace Dependency Hygiene**:
   - Update `crates/monkey-cli/Cargo.toml` to specify `version = "0.1.0"` for `monkey-core` path dependency to eliminate wildcard warning.
   - Configure `deny.toml` skip rules for expected transitive duplicates (`miniz_oxide`, `syn`) to achieve zero warnings.
   - Verify `cargo deny check` passes completely with 0 errors and 0 warnings.
3. **Integration Tests**:
   - `crates/monkey-cli/tests/cli_exit_codes_test.rs`:
     - Test success exits with code 0.
     - Test invalid arguments exit with code 2.
     - Test no device found exits with code 3.
     - Test hardware write without consent exits with code 5.

## Verification
- `cargo deny check` succeeds with zero errors and zero warnings.
- `cargo test --test cli_exit_codes_test` passes.
- `cargo test --workspace` passes.
