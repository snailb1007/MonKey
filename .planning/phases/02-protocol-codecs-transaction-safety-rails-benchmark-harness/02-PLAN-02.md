# Plan 02: Protocol Transaction State Machine & Hardware Safety Rails

## Goal
Implement a robust protocol transaction engine with RAII-guarded lifecycle management, state machine validation, and capability matrix safety rails that prevent unauthorized flash writes and dangerous bootloader commands.

## Tasks
1. Add `SafetyError` in `crates/monkey-core/src/error.rs` for safety rail violations (e.g. `ForbiddenOpcode`, `DirectFlashWriteProhibited`, `InvalidTransactionState`, `CapabilityViolation`).
2. Implement `crates/monkey-core/src/protocol/safety.rs`:
   - `CapabilityMatrix` defining allowed opcodes, maximum packet sizes, and write restrictions per interface.
   - Opcode whitelist verification (`0x18`, `0x13`, `0x20`, `0x11`, `0x02`, `0xF0`, `0xF5`).
   - Blacklist check rejecting bootloader/DFU/ISP opcodes (`0x55`, `0x7140`, `0xFD`, etc.).
   - `WriteMode` distinction: `RamPreview` (no `0x02` commit sent) vs `FlashPersist` (explicit commit allowed only under guarded conditions).
3. Implement `crates/monkey-core/src/protocol/transaction.rs`:
   - `TransactionState`: `Idle`, `Started`, `Active`, `Committed`, `Ended`, `Aborted`.
   - `TransactionManager` wrapping a `Transport` implementation.
   - `TransactionGuard<'a, T>` RAII guard that sends `0xF0` (End) upon Drop if not already terminated.
4. Export transaction and safety types in `crates/monkey-core/src/protocol/mod.rs`.
5. Author comprehensive unit & integration tests in `crates/monkey-core/tests/transaction_safety_test.rs` using `MockTransport`.

## Verification
- Transaction lifecycle states strictly transition in valid order.
- Dropping an active `TransactionGuard` sends `0xF0` clean-up packet to hardware.
- Attempting unwhitelisted opcodes returns typed `SafetyError::ForbiddenOpcode`.
- RAM preview mode succeeds without issuing a flash commit (`0x02`).
