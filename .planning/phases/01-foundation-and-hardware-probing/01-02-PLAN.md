# Phase 1 Plan 02: Dual-Interface HID Discovery, HidTransport, and Heartbeat State Detection

**As a** keyboard user or developer, **I want to** discover and probe my Monka 3075 Pro over USB HID, **so that** I can verify device identity and connection health without triggering OS security prompts.

<objective>
Implement concrete hardware device discovery and userspace HID transport abstraction wrapping `hidapi::HidDevice`. Disambiguate composite Interface A (`0xFF68:0x0061` bulk pipe) and Interface B (`0x000C:0x0001`/`0xFFFF` control pipe) using `(UsagePage, Usage)` tuples on macOS with interface-number fallbacks. Handle Report ID 0 userspace prefix byte framing, non-exclusive device opening via `macos-shared-device`, and connection state heartbeat detection.

Purpose: Provide safe, non-exclusive hardware access to the Monka 3075 Pro's dual USB endpoints without detaching system keyboard drivers or triggering TCC input monitoring warnings.
Output: `device.rs` discovery module, `hid.rs` transport implementation conforming to `Transport`, and unit tests for interface disambiguation and report framing.
</objective>

    Implement Report ID 0 buffer framing per D-02 and RESEARCH.md §Report ID 0 handling:
    - In `write_bulk(&mut self, report_id: u8, data: &[u8]) -> Result<usize, TransportError>`: when `report_id == 0`, allocate a temporary buffer with leading byte `0x00` followed by `data` payload, invoking `self.device.write(&buf)`. The leading `0x00` tells `hidapi` this is an unnumbered report, which macOS `IOHIDDeviceSetReport` strips before wire transmission. Return the count of payload bytes written.
    - In `send_feature_report(&mut self, data: &[u8]) -> Result<(), TransportError>`: invoke `self.device.send_feature_report(data)`, returning `Ok(())` or mapping error to `TransportError::HidError`.
    - In `get_feature_report(&mut self, report_id: u8, buf: &mut [u8]) -> Result<usize, TransportError>`: ensure `buf[0] = report_id`, invoke `self.device.get_feature_report(buf)`, and return bytes read.
    - In `read_input_report(&mut self, buf: &mut [u8], timeout_ms: i32) -> Result<usize, TransportError>`: invoke `self.device.read_timeout(buf, timeout_ms)`. If return is 0, map to `TransportError::Timeout`.

    Define `ConnectionState` enum with variants `WiredUsb`, `WirelessAwake`, and `WirelessSleeping`. Implement `detect_connection_state(&mut self) -> Result<ConnectionState, TransportError>` per DISC-05: query device status using non-destructive reads with finite timeout (e.g. 50ms) and evaluate response or timeout behavior without emitting any flash writes or DFU mode triggers per D-12.

| Kernel IOHIDManager → Userspace `hidapi` | OS driver boundary delivering raw HID reports into application memory |
| Userspace Buffer → `hidapi` C ABI | Buffer pointer handoff across Rust / C ABI boundary |
| Hardware Device State → Connection Detector | Unreliable wireless dongle connectivity and sleep transitions |
