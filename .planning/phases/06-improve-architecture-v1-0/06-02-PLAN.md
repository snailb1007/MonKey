# Phase 6 Plan 02: MonkaDevice Lifecycle & InterfacePolicy Core Engine (Wave 2)

**As a** developer and driver architect, **I want to** introduce a unified `MonkaDevice` concrete coordinator, policy-driven interface resolution, granular error categorization, and non-fail-fast diagnostic inspection in `monkey-core`, **so that** device lifecycle and safety ownership are centralized without breaking Rust's borrow rules.

<objective>
Implement the concrete `MonkaDevice` struct in `crates/monkey-core/src/device.rs`, centralizing `SafetyRails` and `Transport` ownership. Introduce `InterfacePolicy` to declare interface requirements, `OpenError` to structure initialization stages, and `MonkaDevice::diagnose()` to provide non-fail-fast diagnostic data. Expose borrow-safe deep module operations that manufacture `SafeTransport` internally for LCD, RGB, probing, and benchmarks.
</objective>

  <name>Task 1: Implement InterfacePolicy, OpenError, and MonkaDevice lifecycle tracer slice</name>
  <files>crates/monkey-core/src/device.rs, crates/monkey-core/src/lib.rs, crates/monkey-core/tests/monka_device_test.rs</files>
  <action>
    Implement device lifecycle types and constructors in `crates/monkey-core/src/device.rs`:
    - Define `InterfacePolicy` enum per decision D-02:
      - `PreferB`: Interface B first, fallback to Interface A (used by `rgb`).
      - `RequireA`: Interface A only; hard fail if missing (used by `lcd`).
      - `RequireB`: Interface B only; hard fail if missing (used by `probe`).
      - `BulkFirst`: Interface A then Interface B (used by `bench` when running bulk transfers).
      - `ControlFirst`: Interface B then Interface A (used by `bench` when running feature/transaction transfers).
      - `Any`: Open whatever valid Monka interface is available.
    - Define granular `OpenError` enum per decision D-03:
      - `HidInit(#[from] TransportError)`
      - `NoDevice`
      - `InterfaceUnavailable(InterfaceRole)`
      - `InterfaceOpenFailed(InterfaceRole, TransportError)`
    - Define `MonkaDevice` concrete struct per decisions D-01 and D-04:
      - Fields: `transport: Box<dyn Transport>`, `safety: SafetyRails`, `device_set: Option<MonkaDeviceSet>`, `role: Option<InterfaceRole>`, `is_wireless: bool`.
    - Implement constructors and lifecycle methods:
      - `MonkaDevice::open(policy: InterfacePolicy) -> Result<Self, OpenError>`: scans via `find_monka_device_sets`, resolves `policy`, opens endpoint handle with `open_device_path`, and wraps in `HidTransport`.
      - `MonkaDevice::from_transport(transport: Box<dyn Transport>) -> Self`: headless/test constructor fulfilling the single test seam principle (D-01).
      - Fluent builder helpers: `with_device_set`, `with_hardware_writes_allowed`, `with_wireless`.
      - `MonkaDevice::discover() -> Result<Vec<MonkaDeviceSet>, OpenError>`: discovery helper without opening endpoints.
      - Accessors: `is_wireless(&self) -> bool`, `role(&self) -> Option<InterfaceRole>`.
    - Re-export `MonkaDevice`, `InterfacePolicy`, `OpenError` in `crates/monkey-core/src/lib.rs`.
    - Create `crates/monkey-core/tests/monka_device_test.rs` validating:
      - `MonkaDevice::from_transport(Box::new(MockTransport::new()))` creates test device with working builder methods.
      - `InterfacePolicy::resolve_policy` correctly resolves Interface A and Interface B for each policy variant and errors when an interface is missing.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI Caller → MonkaDevice Lifecycle | User input / parameters requesting device open and capability queries |
| MonkaDevice → OS HID Manager | Opening USB device paths across Interface A and Interface B |
| Probing / Discovery → Hardware State | Read-only interrogation of MCU reports without modifying persistent settings |
